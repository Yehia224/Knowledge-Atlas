## 2. Conceptual Model Comparison

| Ref | Framework | Organizing principle | Useful Atlas capability | Limit / decision |
|---|---|---|---|---|
| S01 | BFO (ISO 21838-2:2021) | Continuants and occurrents; realist upper categories | Object/process/property/role distinctions, dependence and participation | Not a curriculum or navigation model; use as comparative reference, not wholesale adoption |
| S02 | DOLCE (ISO 21838-3:2023) | Endurants, perdurants, qualities and abstracts; descriptive commitments | Common-language ambiguities, qualities, social/technical concepts | Requires explicit philosophical alignment; not automatically equivalent to BFO |
| S03 | SUMO | Formal upper and domain ontology, linked to WordNet | Formal class and relation vocabulary, lexical mapping | Word mapping is not identity proof; audit mapping and licence; no global import |
| S04 | CIDOC CRM 7.1.3 | Historical events with actors, objects, time and place | Historical provenance and event-based connections | Domain-oriented, not a universal scientific or educational taxonomy |
| S05 | SKOS | Concepts, labels, concept schemes, semantic hierarchy and collections | Multilingual thesaurus, multiple views, scheme mapping | broader is not automatically OWL subclass or physical part-of; collections are not concepts |
| S06 | OWL 2 | Classes, individuals, properties and axioms | Formal semantics and inference when needed | Open-world semantics do not enforce required record completeness; no framework selection yet |
| S07 | SHACL | Data constraints for RDF graphs | Structural validation, cardinality and typing | Passing shapes does not prove factual truth; use analogous checks in non-RDF prototypes |
| S08 | PROV-O | Entity, Activity, Agent and derivation | Evidence, version and review lineage | Does not establish claim correctness or owner approval |
| S09 | Getty AAT | Facets, hierarchical thesaurus and guide terms | Form vs discipline; display-only group headings | Art/architecture scope, not whole-world classification |

## 3. Candidate Entity and Relationship Register

Not a final upper ontology. Keep the following independently addressable record families where the task requires them.

| Family | Example | Identity criterion | Not equivalent to |
|---|---|---|---|
| Referent / entity | a particular refrigerator | physical/historical identity | its name or article |
| Class / type | refrigerator | criteria for class membership | a particular refrigerator |
| Concept | thermodynamic temperature | intended meaning and scope | string or external ID |
| Term / label | temperature / درجة الحرارة | lexical form, language, sense | concept itself |
| Claim | a heat exchanger transfers energy by heat between streams under specified conditions | proposition and qualifiers | evidence or verdict |
| Record / version | record X, revision 2 | immutable ID plus revision | referent itself |
| Collection / navigation group | HVAC learning topics | stated inclusion purpose | an ontological class by default |
| Relationship assertion | X uses Y | endpoints, predicate, direction, context | browse placement |
| Learning unit | lesson on temperature | objective, audience and sequence | canonical concept |
| Research task | verify HVAC role boundary | question, scope, evidence target | new verified knowledge |
| Source / evidence | edition and passage | source identity, locator, version | claim correctness |

A concept may represent a class, individual, quantity, process or other referent. Do not force every record to denote a single real-world object. Candidate domain families: material object/device, process/event, quality/quantity kind, information artifact/model, mathematical object, role/occupation, organization, place, time interval, service/activity, discipline and resource. These are test vocabulary, not the adopted top hierarchy.

### Predicate register (candidate)

| Predicate | Direction and guard | Closure / inference |
|---|---|---|
| subclass_of | class → class; genuine inclusion | transitive under same semantics; no cycle between distinct strict classes |
| instance_of | individual → class | not transitive itself |
| part_of | entity → whole; kind and time scoped | do not assume unrestricted transitivity |
| has_browse_member | collection → record/collection | navigation only; chosen view acyclic |
| uses_knowledge | activity/field → concept | no automatic prerequisite inference |
| performs | role holder/person → activity; role-type version can describe typical tasks separately | qualified; not all members always perform |
| produces | activity/event → artifact/result | evidence and context required |
| participates_in | person/object → event | time and role may be relevant |
| occurred_at | event → place | preserve alternative/uncertain locations |
| has_time_span | event → interval | preserve precision and bounds |
| expressed_by | concept → lexical label | language and sense required |
| close_match / exact_mapping | concept → concept across schemes | exact is strong; no automatic ID deletion; close not transitive |
| supported_by | claim → evidence | evidence locator and source version required |
| teaches | learning unit → concept/competency | not classification |
| requires_before | prerequisite → learning target | strict prerequisite subgraph must be acyclic for a given path/context |
| related_to | concept ↔ concept | weak fallback, nontransitive; prefer a more precise relation |

For every assertion store assertion ID, subject/predicate/object, qualifiers, source and precise locator, evidence type, review status and reviewer, version, decision rationale. Keep fact status, artifact approval and release status distinct. Unknown ≠ false; conflicting claims coexist pending reconciliation.

## 4. Structural Rules Comparison

| Element | Domain-first historical | Entity-type-first historical | Candidate navigation-first semantics |
|---|---|---|---|
| Garden | independent domain, depth | broad grouping by nature of entities | high-level question/audience/scope with stable purpose and nontrivial coverage |
| Tree | coherent family inside domain | coherent subtype/topic family | grouping defined by explicit membership rule |
| Branch | semantic subdivision | browse grouping | intermediate subgroup or edge, separate identifiers for each meaning |
| Leaf | terminal in current decomposition | concept endpoint | position in a view snapshot; expandable, not atomic by definition |
| Node | any unit of structure | typed knowledge item | graph vertex; qualify as entity/concept/collection/task/lesson |
| Root | foundation in some uses | typed semantic link in some uses | reserve tree root for top vertex; label other relations by predicate |
| Gate | readiness | not mandatory | learning assessment/prerequisite collection, not ontological superclass |

Candidate creation criteria: Garden requires coherent user need, sufficient distinct scope, reusable subdivisions and evidence that a filter/collection would not suffice. Tree requires stated grouping axis, siblings and boundary. Branch requires one grouping criterion at that level, explicit exceptions. Leaf is current terminal position only; expanding it keeps ID and history. No fixed number of children or depth. Group memberships may be nonexclusive across views; no unqualified mixed sibling claims. Preserve original historical paths even when experimenting.

## 5. Candidate Recursive Expansion and Search

USSP remains the historical method. Extension proposed for review:
1. Define a root question, scope, inclusions/exclusions, evidence requirements and depth.
2. Inspect existing source inventories and IDs. Create search scopes, not automatic concept records.
3. Search each meaningful semantic concept separately; breadth-first siblings before selective depth; cross-links do not reset depth or force recursion.
4. For each discovered term, determine meaning; search existing IDs, aliases and scoped definitions; test identity and type.
5. Route as REUSE, LABEL, NEW_CANDIDATE, NEW_RELATION, NAVIGATION_ONLY, SUPPORTING_DETAIL, CONFLICT, or OUT_OF_SCOPE. No automatic approval; preserve provenance.
6. New candidate gets its own scoped task in a bounded next round. Verify links separately. Track visited (identity, scope, source/version) to prevent recursive re-search; mark reopens when evidence changes.
7. Log negative findings, unresolved gaps, scope changes and conflicts. Practical saturation is per scope, not global. Stop when major categories stable and explicit completion tests satisfied, not when a target count is reached.

Separate graph kinds: semantic facts (what it is/does), classification (typed membership), navigation (how to find), search task decomposition (what to investigate), learning (what to understand and in what order). Search is operational, not a fifth kind of scientific fact. Visual UI and storage engine remain open.

## 7. Evidence-based Decision Matrix

Qualitative assessment by this author, not benchmark measurements. H = historical continuity; S = semantic integrity; B = browsing flexibility; L = learning fit; M = migration burden (low preferred).

| Option | H | S | B | L | M | Rationale / blocking issue |
|---|---|---|---|---|---|---|
| A domain tree alone | High Sep, mixed Nov | Low | Medium | Low | Medium | Domain overlap forces duplication or overloaded parents |
| B entity-type tree alone | High Energy | Medium | Low–medium | Low | High | Mixes logical category and user grouping unless carefully constrained |
| C one formal upper ontology for everything | Low–medium | Potentially high after mappings | Low alone | Low alone | High | Philosophical commitments, mapping and training burden; does not solve interface |
| D faceted SKOS-style catalogue alone | High browse continuity | Medium for labels; low for formal assertions | High | Medium with external path | Medium | Broader/related insufficient for all causal, engineering and historical claims |
| E separate semantic layer + views + tasks + learning | High if crosswalk retains IDs | High in principle | High | High | Medium–high | Added governance and complexity; must prove small vertical slice, not assumed approved |

Propose testing E as a reversible hypothesis, while preserving A/B/D as possible views and comparing C mappings selectively. No selection of Garden list, upper ontology, RDF/JSON format or frontend framework. Qualitative ratings must be re-evaluated using real legacy records, search tasks and user tests.
